# Map data from source, stage 1: the build for stations — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `npm run build:data` generates every station's and Zennor's map data from `~/dev/empyreal`, with the look in `data/tweaks/*.json`. Every place draws exactly as it does today, except for T.I.S.S. differences that the report lists.

**Architecture:**
- **The build:** a Node build in `scripts/source/` reads the YAML, filters it, places rooms, resolves the look from the tweak files, and writes `ui/data/*.js`, a place index and `data/sync-report.json`.
- **No drawing changes:** in this stage the drawing code is unchanged. Small adapters in `ui/lib/look.js` turn a generated file's `look` back into the spec shapes the builders already take (`DECKS`, `DRUMS` and `TOWNS` entries, T.I.S.S.'s room fields). Stage 2 replaces the adapters.
- **The check:** golden SVG renders, recorded before anything moves, prove that nothing changed on screen.

**Tech Stack:** Node ESM, vitest 2, `yaml` (new dev dependency), `happy-dom` (new dev dependency, golden tests only).

**Spec:** `docs/superpowers/specs/2026-10-26-map-data-from-source-design.md` (approved 2026-10-26). Read its sections "What the build keeps", "Placing rooms", "The generated files", "Tweak files", "The sync report", "Moving over" and "The sync routine" before starting.

## Global Constraints

- Never write to `~/dev/empyreal`. Read it only. The build takes `--source DIR` (default `~/dev/empyreal`).
- Generated files start with `// GENERATED by npm run build:data from empyreal <sha>. Do not edit.` Nothing hand-edits them.
- The build never writes `data/tweaks/*.json`.
- Kept room fields: `id, name, address, exits, closed, gravity, flags, district, canopy, car`. Nothing else, ever: no `desc`, `features`, `keywords`, `devices`, `machines`, `berth`, `barber`, `off` or `oneway`.
- Allowed flags: `berth`, `airlock`, `outdoors`, `listed`. Others are dropped and reported.
- Exits are kept as the source writes them (an id, or `{to, via, seconds}`), under the source's direction words.
- Tweak files key rooms by local id (`market`, not `orrin.market`). Unknown keys anywhere in a tweak file are a build error naming the file and key.
- Paint values are palette names from `data/tweaks/palette.json`. An unknown name is a build error.
- `ui/` stays plain browser ES modules with no bundler. `scripts/` and `dev/` are not packed.
- Write code that reads like the surrounding code: its comment density, naming and idiom.

## Review Focus

1. **A room renamed or removed in the source while a tweak still names it.** The build must warn ("orphaned tweak") and still succeed, never crash or drop the place. *Test in Task 4.*
2. **A source area with no layout and no tweak file**, such as a new `none` area that isn't Zennor or Wenna. The build must skip drawing data for it, list it in the report under "new places, no builder", and not fail. *Test in Task 5.*
3. **A wheel address the rules can't place** (`Hub, freight`) with no `place` tweak. The room stays out of the generated rooms and appears under "needs a place". With the tweak, it's placed at the tweak's coordinates. *Test in Task 3.*
4. **Running the build twice with no source change.** The second run writes byte-identical files and a report with no changes, so a sync commit is empty when nothing changed. *Test in Task 5.*
5. **`--source` pointing at a missing or partial checkout.** The build stops with one clear message naming the missing path, and writes nothing. *Test in Task 5.*

**Files:**

- [ ] **Step 1: Write the failing tests.**
  - **Paint precedence:** the room's own `paint`, else `paintDistricts[district]`, else `district` if it's a palette name, else the kind default.
    - The kind defaults are: a decks passage (name equals address) → `"midring"`; a room flagged `berth` → `"docks"`; any other room → `"industrial"`. Only new, untweaked places see them: every place drawn today gets paint for every room from its tweak file or its districts, and Task 7 pins that.
  - **Inheritance:** `like` merges its source first. `paint` and `paintDistricts` merge key by key. `fixtures` replace as a whole. Sections merge key by key. A chain `a like b like c` works. A cycle is an error naming the chain.
